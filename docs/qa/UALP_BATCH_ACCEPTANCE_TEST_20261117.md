## Решение владельца

«Мое участие снизить до минимума. Пусть наберётся потом протестом».

Владелец не обязан проходить каждый завершённый технический блок сразу. Отложенная приёмка НЕ равна USER_ACCEPTED. Процесс: работа в пределах уже разрешённого блока → самостоятельные автоматические проверки → точный TEST checkpoint/receipt → объединённый короткий сценарий проверки после нескольких небольших блоков. Время и объём user acceptance фиксируются в конце, а не после каждой кнопки.

Не запускать необозначенно новые долгие работы, дополнительные Codex/агенты/платные API или PROD. Новые крупные бизнес-решения, схемы/владельцы данных, платные сервисы, публикация пользователям, новый тест с незавершённой лицензией — отдельное явное согласование. Без такого решения выполняются только уже разрешённые безопасные блоки; задержка ручной приёмки не разрешает main merge.

## Отложенный единый сценарий владельца (пока НЕ запускать)

Один короткий проход в прежнем приложении на телефоне:
1. Открыть UALP через прежний значок/тот же домен; проверить что авторизация и первичное согласие не повторяются.
2. «Мой профиль» → «Подготовить сводку» → проверить обе методики и баллы; «История тестов» → «К профилю» → убедиться, что сводка скрылась. Повторное создание работает.
3. «На главную» → «Мой маршрут» → убедиться, что фактические завершённые тесты отмечены, а будущие ICAR/профессии и обучение имеют честный статус; перейти в профиль/на главную без нового ввода пароля.
4. Числовое сравнение двух сохранённых прохождений одной методики проверять только если реально имеются два совместимых прохождения; не заставлять владельца проходить 60 вопросов ради QA.
5. В одном старом сохранённом результате из истории посмотреть строку «версия анкеты · записано · проверка методики». Она должна отличаться от версий алгоритма и не сообщать неподтверждённую валидность.
6. На этом же экране убедиться, что видны шесть полос и значения с правильным знаменателем (4 или 40). Не сравнивать полосы двух разных методик как нормированные показатели.

Целевой объём участия: **одна объединённая короткая проверка на телефоне**, только после технической готовности всех согласованных блоков в текущем пакете. Оценивать фактическое время и найденные дефекты, не обещать результат заранее.
